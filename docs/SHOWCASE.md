# Demonstrating ProofPatcher

Use the local app and a repository that you are authorized to show. The demo can cover:

1. A public pull request, its changes and a concise Muse finding.
2. The controlled checkout example, including a rejected shortcut and a passing repair.
3. The dedicated issue → Muse proposal → isolated fixture checks → draft PR flow on the dedicated test repository, showing how an identical existing draft (such as draft PR #14) is linked instead of duplicated, and noting that the observation covers only the included fixture cases.
4. A bot-attributed comment that exists on GitHub, identified as an existing result if it is not created during the demonstration.
5. A short terminal status or review result.
6. How Muse, Hari, supported checks and maintainer decisions fit together.

The checkout example is a controlled fixture. A PR review, a checkout verification, and a dedicated test issue are separate workflows unless the demonstration actually connects them. The fixture observation applies only to its included cases, not arbitrary code. Use real application results and make their scope clear. Keep credentials, unrelated tabs and private repository contents out of captures.
